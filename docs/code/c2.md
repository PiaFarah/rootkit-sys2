# c2.c — Le programme C2

`attacking_program/c2.c` est le programme de Command & Control. Il tourne dans l'espace userland de la VM Attaquante, écoute sur un port TCP, et quand un rootkit se connecte il l'authentifie puis propose un shell interactif.

---

## `fnv1a_hash` — calculer le hash du mot de passe

```c
static uint32_t fnv1a_hash(const char *str)
```

Implémente FNV-1a 32-bit. Les deux constantes magiques :

- Offset de base : `2166136261U` (valeur initiale de l'accumulateur)
- Nombre premier : `16777619U` (facteur de multiplication)

L'algorithme XOR chaque octet avec l'accumulateur puis multiplie par le nombre premier. Le résultat est un entier 32-bit non signé, affiché en hexadécimal sur 8 caractères.

Cette même logique est réimplémentée en Python one-liner dans `install_persistence.sh`. Les deux doivent produire exactement le même résultat pour la même entrée. Vérifiable manuellement en comparant les sorties pour un mot de passe connu.

---

## `write_all` — envoyer un buffer complet

```c
static int write_all(int fd, const char *buf, size_t len)
```

`write` sur un socket n'est pas garantie d'envoyer tous les octets en un seul appel : le kernel peut en envoyer moins si les buffers sont pleins. `write_all` boucle jusqu'à ce que tous les octets soient envoyés. C'est un wrapper indispensable pour tout protocole réseau fiable.

---

## `read_password` — saisir le mot de passe sans écho

```c
static int read_password(char *buf, size_t size)
```

Cette fonction est appelée après que le rootkit se connecte. Elle affiche `WLKOM password:` et désactive l'écho terminal (`ECHO` via `termios`) si stdin est un TTY, pour que le mot de passe ne s'affiche pas à l'écran pendant la saisie.

```c
new_term.c_lflag &= ~ECHO;
tcsetattr(STDIN_FILENO, TCSAFLUSH, &new_term);
```

Elle restaure les paramètres du terminal après la saisie, que celle-ci réussisse ou non. Si stdin n'est pas un TTY (C2 piloté par un script), elle lit simplement sans tenter de modifier le terminal.

## `wait_for_command_or_disconnect` — multiplexer stdin et le socket

```c
static int wait_for_command_or_disconnect(int client_fd)
```

Problème : si le rootkit se déconnecte pendant qu'on attend une saisie utilisateur, `fgets` sur stdin bloquerait indéfiniment. La solution est un `select` sur les deux descripteurs en même temps.

```c
FD_SET(STDIN_FILENO, &readfds);
FD_SET(client_fd, &readfds);
ret = select(max_fd + 1, &readfds, NULL, NULL, NULL);
```

Si `client_fd` devient lisible, on sonde avec `recv(..., MSG_PEEK)`. Si `recv` retourne 0 ou négatif, la connexion est perdue et la fonction retourne 0. Si stdin est prêt, elle retourne 1 (commande disponible). C'est ce qui permet d'afficher `[!] Connection lost` immédiatement au lieu d'attendre que l'opérateur tape une commande.

## `main` — structure générale

### Parsing des arguments et socket serveur

```c
int port = atoi(argv[1]);
```

Le C2 prend un seul argument : le port. Le mot de passe n'est pas en argument de ligne de commande, il est demandé interactivement après chaque connexion.

`SO_REUSEADDR` est positionné sur le socket serveur pour permettre de relancer le C2 immédiatement après un crash sans attendre l'expiration de `TIME_WAIT` sur le port.

### Flux par connexion

À chaque connexion entrante :

1. Le C2 affiche l'IP du rootkit connecté
2. Il appelle `read_password` pour demander le mot de passe à l'opérateur
3. Il calcule `fnv1a_hash(password)` et envoie `AUTH %08x\n` chiffré au rootkit
4. Il lit la réponse chiffrée avec un timeout court : si ce n'est pas `AUTH_OK`, il ferme et remet le socket en attente

```c
snprintf(auth_msg, sizeof(auth_msg), "AUTH %08x\n", fnv1a_hash(password));
write_encrypted(client_fd, auth_msg, strlen(auth_msg), session_key, &tx_pos);
```

### Boucle de commandes

Après authentification, le C2 présente un prompt `c2_shell>` et entre dans une boucle :

1. `wait_for_command_or_disconnect` attend stdin ou une déconnexion
2. `fgets` lit la commande
3. `write_encrypted` l'envoie au rootkit
4. Le C2 lit et déchiffre la réponse en streaming jusqu'à trouver le marqueur `--- End of Output ---\n\n`

La détection du marqueur gère la fragmentation TCP : le marqueur peut arriver à cheval sur deux `read`. La fonction maintient un buffer `tail` des derniers octets reçus et concatène avec le nouveau chunk pour tester la présence du marqueur.

---

## Ce que le C2 ne fait pas

Le C2 est volontairement minimal : une seule connexion à la fois, pas de multiplexage, pas de reprise de commande en cours si le rootkit redémarre. Le chiffrement actuel protège surtout la démo Wireshark contre les commandes et sorties visibles en clair ; ce n'est pas un protocole cryptographique robuste de production.
