# c2.c — Le programme C2

`attacking_program/c2.c` est le programme de Command & Control. Il tourne dans l'espace userland de la VM Attaquante, écoute sur un port TCP, et quand un rootkit se connecte il l'authentifie puis propose un shell interactif.

Le fichier fait ~180 lignes. Il est beaucoup plus simple que `wlkom.c` : pas de contraintes kernel, toutes les API POSIX habituelles sont disponibles.

---

## `fnv1a_hash` — calculer le hash du mot de passe

```c
static uint32_t fnv1a_hash(const char *str)
```

Implémente FNV-1a 32-bit. Les deux constantes magiques :

- Offset de base : `2166136261U` (valeur initiale de l'accumulateur)
- Nombre premier : `16777619U` (facteur de multiplication)

L'algorithme est simple : pour chaque octet de la chaîne, XOR avec l'accumulateur, puis multiplier par le nombre premier. Le résultat est un entier 32-bit non signé, affiché en hexadécimal sur 8 caractères.

Cette même fonction existe côté kernel dans `install_persistence.sh` (en Python one-liner) pour calculer le hash à l'installation, et côté C2 pour générer le hash à envoyer au rootkit. Les trois doivent produire exactement le même résultat pour la même entrée.

## `write_all` — envoyer un buffer complet

```c
static int write_all(int fd, const char *buf, size_t len)
```

`write` sur un socket n'est pas garantie d'envoyer tous les octets en un seul appel — le kernel peut en envoyer moins si les buffers sont pleins. `write_all` boucle jusqu'à ce que tous les octets soient envoyés. C'est un wrapper indispensable pour tout protocole réseau fiable.

## `main` — structure générale

Le `main` fait tout : parsing des arguments, création du socket serveur, accept, et boucle de commandes.

### Parsing des arguments

```c
int port = atoi(argv[1]);
const char *password = argv[2];
```

Le C2 prend deux arguments obligatoires : le port et le mot de passe en clair. Si l'un des deux manque, il affiche l'usage et sort. Le mot de passe n'est jamais stocké dans un fichier — il est passé en ligne de commande et converti en hash immédiatement.

### Création du socket serveur

```c
setsockopt(server_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
```

`SO_REUSEADDR` est indispensable pendant le développement. Sans cette option, si le C2 est tué et relancé rapidement, le port reste en état `TIME_WAIT` pendant quelques secondes et `bind` échoue avec `Address already in use`. Avec `SO_REUSEADDR`, on peut relancer immédiatement.

### Envoi de l'authentification

```c
snprintf(auth_msg, sizeof(auth_msg), "AUTH %08x\n", fnv1a_hash(password));
write_all(client_fd, auth_msg, strlen(auth_msg));
```

Dès que le rootkit se connecte, le C2 envoie immédiatement le hash d'authentification. C'est le C2 qui s'authentifie auprès du rootkit, et non l'inverse — le rootkit est passif, il vérifie que celui qui se connecte connaît le bon secret.

### Boucle de commandes

```c
while (fgets(cmd, sizeof(cmd), stdin) != NULL) {
    write_all(client_fd, cmd, strlen(cmd));
    // lire réponse jusqu'à "--- End of Output ---\n\n"
}
```

`fgets` lit une ligne de stdin (l'entrée de l'utilisateur dans le terminal). Elle est envoyée directement au rootkit via le socket. Ensuite, le C2 lit la réponse ligne par ligne jusqu'à trouver le marqueur de fin `--- End of Output ---`.

### Affichage horodaté

```c
time_t now = time(NULL);
struct tm *t = localtime(&now);
printf("[%02d:%02d:%02d] ", t->tm_hour, t->tm_min, t->tm_sec);
```

Chaque événement (connexion, déconnexion, réponse) est préfixé d'un horodatage `[HH:MM:SS]`. C'est utile pour corréler les événements entre le C2 et les logs `dmesg` de la victime.

## Ce que le C2 ne fait pas

Le C2 est volontairement minimal :

- Pas de chiffrement : le trafic TCP est en clair. C'est une limitation documentée (voir [Décisions — Authentification](../decisions/password.md)).
- Pas de sessions multiples : le C2 accepte une seule connexion à la fois. Après déconnexion, il remet le `accept` en attente.
- Pas de gestion des erreurs réseau complexe : si le socket se casse en milieu de lecture de réponse, le C2 sort de la boucle et attend une nouvelle connexion.
